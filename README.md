# 📉 Customer Churn Prediction

An end-to-end data science project that predicts which telecom customers are
likely to churn — from raw, messy data through cleaning, exploratory analysis,
SQL-based business reporting, machine learning, and an interactive prediction app.

Built as a complete, portfolio-ready project: every number in this README was
generated by actually running the code in this repo.

---

## 🎯 Problem Statement

Customer churn (customers canceling their subscription) is one of the most
expensive problems for subscription businesses — acquiring a new customer
costs far more than retaining one. This project builds a model that flags
at-risk customers **before** they churn, so a retention team can act on them,
and quantifies which factors drive churn the most.

## 📊 Dataset

A synthetic, telecom-style dataset (5,015 raw rows before cleaning; 5,001
after) with the same shape and structure as the well-known Telco Customer
Churn dataset commonly used in the industry — customer demographics,
account information (contract, billing, payment method), subscribed
services, and charges. It's generated by `src/generate_data.py` with a
built-in churn-probability model, **and deliberately seeded with real-world
data-quality issues**:

- 11 missing `TotalCharges` values
- 14 duplicate rows
- Inconsistent text casing/whitespace in categorical fields

This makes the cleaning step in the notebook meaningful rather than a
formality — exactly the kind of messiness you'd hit with a real data export.

## 🔍 Exploratory Findings

(See `notebooks/01_eda_and_cleaning.ipynb` for the full analysis with charts.)

- **Overall churn rate: 33.0%**
- **Contract type is the single strongest driver of churn:**

  | Contract | Churn Rate |
  |---|---|
  | Month-to-month | 45.2% |
  | One year | 20.3% |
  | Two year | 16.5% |

- **Tenure matters:** churn risk is highest in a customer's first year and
  drops steadily the longer they stay.
- **Fiber optic internet customers churn more** than DSL or no-internet
  customers, despite (or because of) higher monthly bills.
- **Add-on services correlate with retention** — customers without Online
  Security or Tech Support subscriptions churn noticeably more.
- **306 currently-active customers** match the highest-risk profile
  (month-to-month + fiber + no tech support), representing **~$27,981/month
  (~$335,772/year) in revenue at risk** — see SQL query #6.

## 🤖 Modeling Approach

Three classifiers were trained inside a single scikit-learn `Pipeline`
(one-hot encoding + scaling bundled with the model, so there's no
train/test leakage and the saved `.pkl` can score raw-shaped data directly):

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| **Logistic Regression** ⭐ | 73.5% | 57.8% | 72.7% | 64.4% | **0.819** |
| Random Forest | 74.7% | 60.1% | 69.4% | 64.4% | 0.812 |
| Gradient Boosting | 75.9% | 68.0% | 50.9% | 58.2% | 0.818 |

**Logistic Regression was selected** as the best model — it has the highest
ROC-AUC and, importantly for a churn use case, the highest *recall*: catching
73% of customers who actually churn matters more here than raw accuracy,
since the business cost of missing an at-risk customer (a lost customer)
is much higher than the cost of a false alarm (a retention offer sent to
someone who wouldn't have churned anyway).

`class_weight="balanced"` is used to address the class imbalance (67%
retained vs. 33% churned) rather than naively optimizing for accuracy.

## 🖥️ Interactive Demo

`app/streamlit_app.py` is a Streamlit app where you fill in a customer's

## 🗃️ SQL Analysis

`sql/churn_analysis_queries.sql` contains 10 business-facing queries
(churn rate by contract/tenure/payment method, revenue-at-risk, a retention
call list, add-on service impact, etc.) — written to run against the same
dataset once loaded into MySQL, PostgreSQL, or SQLite, for candidates who
want to demonstrate SQL alongside Python.

## 🚀 Quickstart

```bash
git clone <your-repo-url>
cd customer-churn-prediction
pip install -r requirements.txt

python src/generate_data.py       # generate the dataset (already included, but reproducible)
python src/train_model.py         # train models, save the best one + evaluation report
python src/predict.py --input data/raw/customer_churn.csv --output reports/predictions.csv

streamlit run app/streamlit_app.py   # launch the interactive demo
```

Full step-by-step instructions (including troubleshooting) are in
[`RUNBOOK.md`](RUNBOOK.md).
